# 产品取舍

核心用户首先是需要同时评估 AI 产品、客户成功和解决方案方向的求职者。

核心流程：真实画像 → 粘贴并核对 JD → 逐条核对证据来源与边界 → 生成分析 → 用户审查 → 决定投递与后续行动。

要求和证据分层：JD 原文事实、AI 推断、画像事实、待核验事项分开表达。资格状态与任务证据类型分开，不把专业加分项提升为硬门槛；个人、校园、创业经历不自动升级为企业资历。避免没有校准依据的匹配百分比。

开发中的 v2 收紧证据入口：用户明确核对来源和支持边界，服务端提供固定答案槽位；模型负责解释，不自由填写证据标签。部分保存不等于确认，待核对不能进入整份确认。

实际试用反馈推动简化：有效用时由第一次 1136 秒降为第二次 435 秒，控件激活 72→56；第二次确认 10/14，仍有待处理项，主观负担 3/5。这是同一用户的两次虚构试用，不能推导为一般用户效率提升或闭环完成。

暂缓：自动投递、招聘聚合、自动生成完整简历文件、复杂评分、聊天助手。投递 CRUD 和 Dashboard 闭环尚未完成。
